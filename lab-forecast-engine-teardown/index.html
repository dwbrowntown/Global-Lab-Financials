Section 03

The recognition rule, as built

The rule

The entire order cost lands in the fiscal quarter the last part of that SO ships. Nothing spreads, nothing recognises partially. Cost is COALESCE("Item Standard Cost",0) × "Ordered Quantity" summed to order level — the expression your doc reconciled against ten approved ICO totals to the cent.

Fully shipped → recognised on the latest actual ship date. Still open → forecast on the latest scheduled date of the lines still owed, never earlier than the current quarter. Open with no date → current quarter, flagged. Each row is labelled Actual or Forecast, and an order moves between them on its own as lines ship.

Cancellation behaviour, your 7830 case

Cancelled lines are excluded before anything is counted. Cancel the open tail of an order and the remaining lines are all shipped, so the order flips to Actual and back-dates itself to the last part that really shipped — no manual step, next refresh. Cancelled lines also carry zero quantity in EDNA, so the dollars net out by construction.

The four filters that cannot be skipped, all validated: Account RLIKE '^[0-9]{5}$' · Line Status <> 'CANCELED' · LEFT("Expense Dept",4) IN (lab codes) · and no Sales Channel filter, which goes blank after the Fusion cutover.

BLOCK A · Finance Cost ForecastReplaces current Block A · executed today

One row per quarter per category, every quarter present from FY24 through two years out. The three refinements over your v2 doc are marked.

WITH lab_lines AS (
  SELECT
    "Order Number"                                         AS SO_NUMBER,
    "Account"                                              AS ACCOUNT_CODE,
    LEFT("Expense Dept", 4)                                AS EXPENSE_DEPT,
    COALESCE("Item Standard Cost", 0) * "Ordered Quantity" AS LINE_COST,  -- reconciled to the cent; null = $0 bundle line
    "Actual Ship Date"                                     AS ACTUAL_SHIP_DATE,
    "Schedule Ship Date"                                   AS SCHEDULE_SHIP_DATE
  FROM EDNA.CONS_INSIGHTS_MART.EDNA_ORDER_MANAGEMENT_REPORT
  WHERE "Account" RLIKE '^[0-9]{5}$'                       -- free-text notes live in Account
    AND "Line Status" <> 'CANCELED'                        -- else fully-shipped orders read as open
    AND LEFT("Expense Dept", 4) IN ('7030','7110','7120','7130','7140')
    -- NO Sales Channel filter: blank after the Fusion cutover
),
orders AS (
  SELECT
    SO_NUMBER,
    MAX(ACCOUNT_CODE)                                                   AS ACCOUNT_CODE,
    COUNT(*)                                                            AS LINE_COUNT,
    SUM(CASE WHEN ACTUAL_SHIP_DATE IS NULL THEN 1 ELSE 0 END)           AS OPEN_LINES,
    ROUND(SUM(LINE_COST), 2)                                            AS BUDGET_HIT,
    MAX(ACTUAL_SHIP_DATE)                                               AS LAST_ACTUAL,
    -- REFINEMENT 1: scheduled date of the lines STILL OWED, not all lines
    MAX(CASE WHEN ACTUAL_SHIP_DATE IS NULL THEN SCHEDULE_SHIP_DATE END) AS OPEN_SCHED
  FROM lab_lines GROUP BY SO_NUMBER
),
recog AS (
  SELECT o.*,
    -- THE RULE: full cost in the quarter the last part ships.
    -- REFINEMENT 2: an open order can never recognise in a closed quarter.
    -- REFINEMENT 3: open with no date anywhere = current quarter, not dropped.
    CASE WHEN OPEN_LINES = 0 THEN LAST_ACTUAL
         WHEN OPEN_SCHED IS NOT NULL
              THEN GREATEST(OPEN_SCHED, DATE_TRUNC('quarter', CURRENT_DATE()))
         ELSE DATE_TRUNC('quarter', CURRENT_DATE()) END                 AS RECOGNITION_DATE,
    CASE WHEN OPEN_LINES = 0 THEN 'Actual' ELSE 'Forecast' END          AS SPEND_TYPE,
    CASE WHEN LEFT(ACCOUNT_CODE,1) = '2' THEN 'CapEx' ELSE 'OpEx' END   AS BUDGET_CATEGORY
  FROM orders o
),
fiscal AS (
  SELECT r.*,
    CASE WHEN MONTH(RECOGNITION_DATE) >= 7 THEN YEAR(RECOGNITION_DATE)+1
         ELSE YEAR(RECOGNITION_DATE) END                                AS FISCAL_YEAR,
    CASE WHEN MONTH(RECOGNITION_DATE) <= 3 THEN 'Q3'
         WHEN MONTH(RECOGNITION_DATE) <= 6 THEN 'Q4'
         WHEN MONTH(RECOGNITION_DATE) <= 9 THEN 'Q1' ELSE 'Q2' END      AS FISCAL_QUARTER
  FROM recog r WHERE RECOGNITION_DATE IS NOT NULL
),
allowance AS (
  -- the one editable thing in the model. Change here when Finance changes it.
  SELECT cat AS BUDGET_CATEGORY, amt AS QUARTER_BUDGET
  FROM VALUES ('CapEx', 300000), ('OpEx', 100000) AS t(cat, amt)
),
bounds AS (
  SELECT LEAST(MIN(FISCAL_YEAR), 2024) AS MIN_FY,
         GREATEST(MAX(FISCAL_YEAR),
                  CASE WHEN MONTH(CURRENT_DATE()) >= 7 THEN YEAR(CURRENT_DATE())+2
                       ELSE YEAR(CURRENT_DATE())+1 END)                 AS MAX_FY
  FROM fiscal
),
years AS (
  SELECT FISCAL_YEAR FROM (
    SELECT b.MIN_FY + SEQ4() AS FISCAL_YEAR, b.MAX_FY
    FROM bounds b, TABLE(GENERATOR(ROWCOUNT => 25)))
  WHERE FISCAL_YEAR <= MAX_FY
),
spine AS (
  -- every quarter exists even with zero spend: FY27 can never vanish again
  SELECT y.FISCAL_YEAR, q.FISCAL_QUARTER, a.BUDGET_CATEGORY, a.QUARTER_BUDGET
  FROM years y
  CROSS JOIN (SELECT 'Q1' AS FISCAL_QUARTER UNION ALL SELECT 'Q2'
              UNION ALL SELECT 'Q3' UNION ALL SELECT 'Q4') q
  CROSS JOIN allowance a
),
rollup AS (
  SELECT FISCAL_YEAR, FISCAL_QUARTER, BUDGET_CATEGORY,
         COUNT(*)                                                            AS ORDERS,
         ROUND(SUM(CASE WHEN SPEND_TYPE='Actual'   THEN BUDGET_HIT ELSE 0 END),2) AS ACTUAL_SPEND,
         ROUND(SUM(CASE WHEN SPEND_TYPE='Forecast' THEN BUDGET_HIT ELSE 0 END),2) AS FORECAST_SPEND,
         ROUND(SUM(BUDGET_HIT),2)                                            AS TOTAL_COMMITTED
  FROM fiscal GROUP BY 1,2,3
)
SELECT
  'FY' || RIGHT(s.FISCAL_YEAR::VARCHAR,2) || s.FISCAL_QUARTER          AS FYFQ,
  s.FISCAL_YEAR, s.FISCAL_QUARTER, s.BUDGET_CATEGORY,
  COALESCE(r.ORDERS, 0)                                                AS ORDERS,
  s.QUARTER_BUDGET,
  COALESCE(r.ACTUAL_SPEND, 0)                                          AS ACTUAL_SPEND,
  COALESCE(r.FORECAST_SPEND, 0)                                        AS FORECAST_SPEND,
  COALESCE(r.TOTAL_COMMITTED, 0)                                       AS TOTAL_COMMITTED,
  ROUND(s.QUARTER_BUDGET - COALESCE(r.TOTAL_COMMITTED,0), 2)           AS REMAINING_BUDGET,
  ROUND(100.0 * COALESCE(r.TOTAL_COMMITTED,0) / s.QUARTER_BUDGET, 1)   AS PCT_OF_BUDGET,
  CASE WHEN COALESCE(r.TOTAL_COMMITTED,0) >  s.QUARTER_BUDGET       THEN 'Over'
       WHEN COALESCE(r.TOTAL_COMMITTED,0) >  s.QUARTER_BUDGET * 0.9 THEN 'Red'
       WHEN COALESCE(r.TOTAL_COMMITTED,0) >  s.QUARTER_BUDGET * 0.7 THEN 'Yellow'
       WHEN COALESCE(r.TOTAL_COMMITTED,0) =  0                      THEN 'No spend'
       ELSE 'Green' END                                                AS STATUS,
  -- self-maintaining current-quarter flag: the dashboard KPIs filter on this,
  -- so nothing needs re-pointing when the quarter rolls
  ('FY' || RIGHT((CASE WHEN MONTH(CURRENT_DATE()) >= 7 THEN YEAR(CURRENT_DATE())+1
                       ELSE YEAR(CURRENT_DATE()) END)::VARCHAR, 2)
        || CASE WHEN MONTH(CURRENT_DATE()) <= 3 THEN 'Q3'
                WHEN MONTH(CURRENT_DATE()) <= 6 THEN 'Q4'
                WHEN MONTH(CURRENT_DATE()) <= 9 THEN 'Q1' ELSE 'Q2' END)
   = ('FY' || RIGHT(s.FISCAL_YEAR::VARCHAR,2) || s.FISCAL_QUARTER)     AS IS_CURRENT_FQ
FROM spine s
LEFT JOIN rollup r USING (FISCAL_YEAR, FISCAL_QUARTER, BUDGET_CATEGORY)
ORDER BY s.FISCAL_YEAR, s.FISCAL_QUARTER, s.BUDGET_CATEGORY
BLOCK B · Active Order LinesYour doc’s version, kept · two extensions

Line grain, unshipped only. Kept exactly as your executed v2 Block B — including the EBS and Fusion status map (AWAIT_SHIP, EN_SCHEDULED) — with two additions marked below.

SELECT
  "Order Number"                                            AS SO_NUMBER,
  "Ordered Item"                                            AS PART_NUMBER,
  CASE "Line Status"
    WHEN 'CLOSED'               THEN 'Shipped'
    WHEN 'AWAITING_SHIPPING'    THEN 'Awaiting Shipping'    -- EBS
    WHEN 'AWAIT_SHIP'           THEN 'Awaiting Shipping'    -- Fusion
    WHEN 'AWAITING_FULFILLMENT' THEN 'Awaiting Fulfilment'
    WHEN 'EN_SCHEDULED'         THEN 'Scheduled'            -- Fusion
    WHEN 'BOOKED'               THEN 'Booked'
    ELSE COALESCE("Line Status", 'Unknown') END             AS STATUS_LABEL,
  TRIM("Ship To Party Name")                                AS SHIP_TO,
  "Ship To Site Region"                                     AS GEO,
  LEFT("Expense Dept", 4)                                   AS EXPENSE_DEPT,
  "Account"                                                 AS ACCOUNT_CODE,
  CASE WHEN LEFT("Account",1)='2' THEN 'CapEx' ELSE 'OpEx' END AS BUDGET_CATEGORY,
  "Ordered Quantity"                                        AS ORDERED_QTY,
  COALESCE("Shipped Quantity", 0)                           AS SHIPPED_QTY,
  "Ordered Quantity" - COALESCE("Shipped Quantity", 0)      AS QTY_OUTSTANDING,
  ROUND(COALESCE("Item Standard Cost",0) * "Ordered Quantity", 2) AS LINE_COST,
  "Schedule Ship Date"                                      AS SCHEDULE_SHIP_DATE,
  DATEDIFF(DAY, CURRENT_DATE(), "Schedule Ship Date")       AS DAYS_TO_SHIP,
  CASE
    WHEN "Schedule Ship Date" IS NULL                              THEN 'Unscheduled'
    WHEN DATEDIFF(DAY, CURRENT_DATE(), "Schedule Ship Date") < 0   THEN 'Overdue'
    WHEN DATEDIFF(DAY, CURRENT_DATE(), "Schedule Ship Date") <= 7  THEN '0-7 Days'
    WHEN DATEDIFF(DAY, CURRENT_DATE(), "Schedule Ship Date") <= 14 THEN '8-14 Days'
    WHEN DATEDIFF(DAY, CURRENT_DATE(), "Schedule Ship Date") <= 30 THEN '15-30 Days'
    ELSE '30+ Days' END                                     AS SHIP_BUCKET,
  -- EXTENSION 1: where this line's order recognises under the floor rule
  GREATEST(COALESCE("Schedule Ship Date", CURRENT_DATE()),
           DATE_TRUNC('quarter', CURRENT_DATE()))           AS EFFECTIVE_FORECAST_DATE,
  -- EXTENSION 2: days a stale line has sat past its promise - cancellation queue
  CASE WHEN "Schedule Ship Date" < CURRENT_DATE()
       THEN DATEDIFF(DAY, "Schedule Ship Date", CURRENT_DATE()) END AS DAYS_STALE,
  -- fiscal-quarter label of the effective forecast date, for the by-quarter chart
  'FY' || RIGHT((YEAR(EFFECTIVE_FORECAST_DATE)
                 + CASE WHEN MONTH(EFFECTIVE_FORECAST_DATE) >= 7 THEN 1 ELSE 0 END)::VARCHAR, 2)
       || CASE WHEN MONTH(EFFECTIVE_FORECAST_DATE) <= 3 THEN 'Q3'
               WHEN MONTH(EFFECTIVE_FORECAST_DATE) <= 6 THEN 'Q4'
               WHEN MONTH(EFFECTIVE_FORECAST_DATE) <= 9 THEN 'Q1' ELSE 'Q2' END AS FORECAST_FYFQ
FROM EDNA.CONS_INSIGHTS_MART.EDNA_ORDER_MANAGEMENT_REPORT
WHERE "Account" RLIKE '^[0-9]{5}$'
  AND "Line Status" <> 'CANCELED'
  AND LEFT("Expense Dept", 4) IN ('7030','7110','7120','7130','7140')
  AND "Actual Ship Date" IS NULL
ORDER BY "Schedule Ship Date"

BLOCK D · Order Audit & Data QualityReplaces current Block D · one row per order

The audit trail behind every Finance figure, with the DQ flags that police the model’s two assumptions: one account per order, and dates on open orders.

WITH lab_lines AS (
  SELECT
    "Order Number"                                         AS SO_NUMBER,
    "Account"                                              AS ACCOUNT_CODE,
    LEFT("Expense Dept", 4)                                AS EXPENSE_DEPT,
    "Ship To Site Region"                                  AS GEO,
    TRIM("Ship To Party Name")                             AS SHIP_TO,
    "Ordered Quantity"                                     AS ORDERED_QTY,
    COALESCE("Item Standard Cost", 0) * "Ordered Quantity" AS LINE_COST,
    CASE WHEN "Item Standard Cost" IS NULL THEN 1 ELSE 0 END AS ZERO_COST_LINE,
    "Actual Ship Date"                                     AS ACTUAL_SHIP_DATE,
    "Schedule Ship Date"                                   AS SCHEDULE_SHIP_DATE
  FROM EDNA.CONS_INSIGHTS_MART.EDNA_ORDER_MANAGEMENT_REPORT
  WHERE "Account" RLIKE '^[0-9]{5}$'
    AND "Line Status" <> 'CANCELED'
    AND LEFT("Expense Dept", 4) IN ('7030','7110','7120','7130','7140')
)
SELECT
  SO_NUMBER,
  MAX(ACCOUNT_CODE)                                          AS ACCOUNT_CODE,
  CASE WHEN LEFT(MAX(ACCOUNT_CODE),1)='2' THEN 'CapEx' ELSE 'OpEx' END AS BUDGET_CATEGORY,
  MAX(EXPENSE_DEPT)                                          AS EXPENSE_DEPT,
  MAX(GEO)                                                   AS GEO,
  MAX(SHIP_TO)                                               AS SHIP_TO,
  COUNT(*)                                                   AS LINE_COUNT,
  SUM(ZERO_COST_LINE)                                        AS ZERO_COST_LINES,   -- expected non-zero: bundles
  SUM(CASE WHEN ACTUAL_SHIP_DATE IS NULL THEN 1 ELSE 0 END)  AS OPEN_LINES,
  ROUND(SUM(LINE_COST), 2)                                   AS BUDGET_HIT,
  MAX(ACTUAL_SHIP_DATE)                                      AS FINAL_ACTUAL_SHIP,
  MAX(CASE WHEN ACTUAL_SHIP_DATE IS NULL THEN SCHEDULE_SHIP_DATE END) AS OPEN_SCHED,
  CASE WHEN SUM(CASE WHEN ACTUAL_SHIP_DATE IS NULL THEN 1 ELSE 0 END) = 0
       THEN MAX(ACTUAL_SHIP_DATE)
       WHEN MAX(CASE WHEN ACTUAL_SHIP_DATE IS NULL THEN SCHEDULE_SHIP_DATE END) IS NOT NULL
       THEN GREATEST(MAX(CASE WHEN ACTUAL_SHIP_DATE IS NULL THEN SCHEDULE_SHIP_DATE END),
                     DATE_TRUNC('quarter', CURRENT_DATE()))
       ELSE DATE_TRUNC('quarter', CURRENT_DATE()) END        AS RECOGNITION_DATE,
  CASE WHEN SUM(CASE WHEN ACTUAL_SHIP_DATE IS NULL THEN 1 ELSE 0 END) > 0
       THEN 'Forecast' ELSE 'Actual' END                     AS SPEND_TYPE,
  CASE WHEN COUNT(DISTINCT ACCOUNT_CODE) > 1 THEN 'Multiple accounts on one order'
       WHEN SUM(CASE WHEN ACTUAL_SHIP_DATE IS NULL THEN 1 ELSE 0 END) > 0
            AND MAX(CASE WHEN ACTUAL_SHIP_DATE IS NULL THEN SCHEDULE_SHIP_DATE END) IS NULL
            THEN 'Open with no scheduled date - recognised current quarter'
       WHEN MAX(CASE WHEN ACTUAL_SHIP_DATE IS NULL THEN SCHEDULE_SHIP_DATE END) < CURRENT_DATE()
            THEN 'Stale backlog - scheduled date has passed, review for cancellation'
       ELSE NULL END                                         AS DQ_ISSUE
FROM lab_lines
GROUP BY SO_NUMBER
ORDER BY RECOGNITION_DATE DESC
BLOCK E · Department Scope ReviewNew · executed today

Orders coded to a lab department that do not look like lab spend: hardware to a non-Extreme entity, or shipped outside the department’s region. Scoped to the last three fiscal years so 2018-era history does not drown the signal; today it surfaces Green Bay Packers ($11,206) and Infovista, among others.

WITH dept_dim AS (
  SELECT * FROM VALUES
    ('7030','Service Operations - Salem','AMERICAS'),
    ('7110','LATAM TAC',                 'AMERICAS'),
    ('7120','Asia TAC - Chennai',        'APAC'),
    ('7130','EMEA TAC - Reading',        'EMEA'),
    ('7140','Americas TAC',              'AMERICAS')
    AS d(DEPT_CODE, DEPT_NAME, EXPECTED_REGION)
),
orders AS (
  SELECT "Order Number"                       AS SO_NUMBER,
         LEFT("Expense Dept",4)               AS DEPT_CODE,
         MAX("Account")                       AS ACCOUNT_CODE,
         MAX(TRIM("Ship To Party Name"))      AS SHIP_TO,     -- TRIM: names carry stray tabs
         MAX(TRIM("Ship To Site Region"))     AS REGION,
         ROUND(SUM(COALESCE("Item Standard Cost",0) * "Ordered Quantity"),2) AS BUDGET_HIT,
         MAX("Actual Ship Date")              AS LAST_SHIP,
         MIN("Schedule Ship Date")            AS FIRST_SCHED
  FROM EDNA.CONS_INSIGHTS_MART.EDNA_ORDER_MANAGEMENT_REPORT
  WHERE "Account" RLIKE '^[0-9]{5}$'
    AND "Line Status" <> 'CANCELED'
    AND LEFT("Expense Dept",4) IN ('7030','7110','7120','7130','7140')
  GROUP BY 1,2
)
SELECT o.SO_NUMBER, o.DEPT_CODE, d.DEPT_NAME, d.EXPECTED_REGION,
       o.REGION, o.SHIP_TO, o.ACCOUNT_CODE, o.BUDGET_HIT, o.LAST_SHIP,
       TRIM(CONCAT(
         CASE WHEN UPPER(o.SHIP_TO) NOT LIKE '%EXTREME%'
              THEN 'Ship-to is not an Extreme entity.  ' ELSE '' END,
         CASE WHEN UPPER(o.REGION) <> d.EXPECTED_REGION
              THEN 'Region is not ' || d.EXPECTED_REGION || '.' ELSE '' END)) AS REVIEW_REASON
FROM orders o
JOIN dept_dim d ON d.DEPT_CODE = o.DEPT_CODE
WHERE (UPPER(o.SHIP_TO) NOT LIKE '%EXTREME%'
    OR UPPER(o.REGION) <> d.EXPECTED_REGION)
  AND COALESCE(o.LAST_SHIP, o.FIRST_SCHED) >= DATEADD(YEAR, -3, CURRENT_DATE())
ORDER BY o.BUDGET_HIT DESC
